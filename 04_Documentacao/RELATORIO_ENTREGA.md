## 1. Objetivo e continuidade

O Study Hub TI organiza minha trajetória acadêmica e profissional em Tecnologia da Informação. A etapa inicial estabeleceu o perfil, as áreas de interesse e a estrutura por disciplinas. A etapa intermediária amplia essa base com um portfólio web, um projeto pessoal e documentação de versionamento, compartilhamento e publicação.

## 2. Planejamento do repositório

A organização preserva 01_Apresentacao_e_Perfil, 02_Disciplinas_Atuais e 03_Projetos_e_Certificados. Projetos_Academicos e Projetos_Pessoais separam os trabalhos por finalidade. A pasta 04_Documentacao centraliza os procedimentos e o relatório, enquanto docs contém a página estática e o planejador. Cada projeto tem README próprio, descrevendo objetivo, tecnologias, execução, funcionalidades, validação e limitações.

## 3. Projeto acadêmico: Portfólio Web

A página apresenta o perfil de Luís Flávio Góis da Silva, estudante de ADS no CEUB, suas áreas de interesse e seus projetos. Foi construída em HTML e CSS, com navegação por seções e layout responsivo. O código fica em docs/index.html. Pode ser aberto localmente e está preparado para publicação no GitHub Pages. A seção Trajetória relaciona a etapa inicial à intermediária e aponta para as entregas do repositório.

## 4. Projeto pessoal: Ciclo de Estudos

O planejador em docs/ciclo/index.html permite cadastrar disciplina, dia e duração de sessões. JavaScript atualiza a lista e soma a carga semanal. Os dados são armazenados em localStorage, quando disponível, e podem ser exportados em JSON. Há remoção de sessões, limpeza com confirmação e validação de duração inteira entre 10 e 240 minutos. Não há backend ou sincronização entre dispositivos.

## 5. Versionamento e colaboração

O processo proposto usa uma branch de funcionalidade, commits descritivos, envio ao GitHub e Pull Request para main. A tag v1.0.0 deve identificar a primeira versão funcional após sua validação. Uma alteração posterior no rodapé do portfólio demonstra evolução por um segundo commit e PR. CONTRIBUTING.md documenta o fluxo de colaboração. Por ser uma atividade individual, a revisão deve ser descrita como autorrevisão, salvo participação efetiva de outra pessoa.

## 6. Publicação e integração profissional

A publicação planejada usa a branch main e a pasta /docs no GitHub Pages. Após a implantação, o endereço exibido pelo GitHub deve ser testado sem autenticação. O portfólio deve receber links dos documentos, slides e site anteriores que forem utilizados. No LinkedIn, o projeto deve ser incluído com título, descrição e URL pública. A apresentação de aproximadamente cinco minutos deve demonstrar o repositório, os projetos, o histórico e a integração.

## 7. Resultado e próximos passos

O pacote local fornece os arquivos do portfólio, o planejador, a documentação e o roteiro da apresentação. Para concluir a entrega acadêmica, ainda é necessário registrar e enviar os commits, publicar e conferir o Pages, vincular os materiais anteriores, adicionar o projeto ao LinkedIn, gravar e publicar o vídeo e atualizar este relatório com links e evidências reais. Não se declara como concluída nenhuma dessas ações externas apenas pela existência dos arquivos.
